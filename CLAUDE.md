# Waifu and Meme Downloader

Расширение для Firefox и Chrome. Добавляет кнопку скачивания к постам в X (Twitter): видео, GIF (конвертируются в настоящий .gif), картинки.

Полная документация — в `README.md`, включая таблицу диагностики поломок и список уже наступленных граблей. Прочитай его перед серьёзными правками, особенно раздел «Когда сломается».

## Структура

Кроссбраузерность через общий код + два манифеста:
- `manifest.json` — Firefox (background как `scripts`)
- `manifest.chrome.json` — Chrome (background как `service_worker`, плюс permission `offscreen`)

Собирается через `node build.mjs` (запускать из корня репозитория) → `dist/firefox/` и `dist/chrome/`. Эти папки в git не попадают, генерируются заново по требованию. Версия — единый источник правды в `manifest.json`, скрипт сборки сам подтягивает её в chrome-манифест.

Исходники лежат в корне репозитория:
- `inject.js` — работает **внутри страницы твиттера** (не в мире расширения). Перехватывает `fetch`/`XMLHttpRequest`, вытаскивает ссылки на медиа из GraphQL-ответов. Самая хрупкая часть — X меняет структуру без предупреждения.
- `content.js` — изолированный мир расширения. Кнопки, DOM, имена файлов, санитизация путей, пайплайн конвертации GIF.
- `gif-encoder.js` — свой кодировщик GIF89a (median cut + LZW), без зависимостей. Подключается перед `content.js`, отдаётся как `globalThis.XVDGifEncoder`.
- `background.js` — единственное, что умеет качать. Создаёт blob URL (в Firefox сам, в Chrome через offscreen), ждёт завершения загрузки.
- `offscreen.html` / `offscreen.js` — только для Chrome, создаёт blob URL там, где в service worker это невозможно.
- `popup.html` / `popup.js` — настройки, тёмная тема, живое превью пути сохранения.

`build.mjs` кладёт `offscreen.*` в **обе** сборки — они в списке `SHARED`. В Firefox эти файлы просто лежат без дела, это не баг и «чинить» не нужно.

## Правила работы

- Комментарии в коде и README — на русском, интерфейс попапа — на английском. Не переводить одно в другое без явной просьбы.
- После любой правки JS: `node --check <файл>` перед сборкой.
- После правок — `node build.mjs` из корня репозитория, затем предложить, как переустановить расширение в браузере для проверки.
- Версию в `manifest.json` поднимать при каждой пересборке, которая пойдёт на подпись (`web-ext sign` не принимает повторный номер).
- Тестирование — через `about:debugging` (Firefox) или `chrome://extensions` (Chrome) с распакованной папкой из `dist/`. После правок content script нужна полная перезагрузка вкладки твиттера, не только reload расширения.
- Не использовать сторонние npm-библиотеки без явного запроса — текущий подход: минимум зависимостей, весь код читаемый и правится вручную.
- Готовые архивы (.zip) в репозиторий не коммитить — это результат ручной упаковки для передачи файлов, гиту они не нужны.

## Не переименовывать

Префикс `xvd` — наследство от старого имени папки (`xvd-extension/`, исходники подняты в корень 14.08.2026). Имя устарело, но сами строки менять **нельзя**:

- **`"id": "xvd-extension@local.personal"`** в `manifest.json` → `browser_specific_settings.gecko`. Для Firefox id — это тождество расширения. Другой id = другое расширение: слетают настройки пользователя в `storage.local` и рвётся связь с уже подписанными на AMO сборками.
- **`source: "xvd-extension"`** в `postMessage` между `inject.js` и `content.js` — метка канала, по которой получатель отсеивает чужие сообщения со страницы. Значение произвольное, но должно совпадать на обеих сторонах; к имени папки отношения не имеет.
- **Префиксы `xvd-` в CSS-классах** (`xvd-photo-container` и прочие) и **ключи `dataset.xvd*`** (`xvdTweet`, `xvdKey`, `xvdBusy`). Живут одновременно в `content.js` и `style.css`, переименование требует синхронной правки обоих и ничего не даёт.

Если захочется навести красоту — это отдельная задача с полной переустановкой расширения и потерей настроек, а не попутный рефакторинг.

## Подпись и артефакты

- Версия 1.10.2 **уже подписана** на AMO. Тот же номер повторно не примут — перед `web-ext sign` поднимать `version` в `manifest.json`.
- Подписанные `.xpi` и `.amo-upload-uuid` хранятся **вне репозитория**, в `c:\Projects\meme-and-waifu-downloader-artifacts\`. В git им делать нечего, но и терять их не нужно: пересоздать `.xpi` для уже израсходованной версии невозможно.
- `web-ext sign` запускается из `dist/firefox/`, а не из корня.

## Известные хрупкие места (см. README подробнее)

- Адреса картинок в ленте твиттера идут без расширения файла, из API — с ним. Сравнение через `baseMediaKey()`, режет и то и другое.
- React переписывает `className` контейнеров при перерисовке — класс `xvd-photo-container` восстанавливается на каждом проходе, в CSS есть запасной селектор.
- DOM-узлы переиспользуются при скролле — кнопки помнят свою принадлежность через `dataset`, а не WeakSet.
- Размер иконки: 18.75px в ленте, 22.5px на странице поста — определяется через `getComputedStyle` соседней иконки, не хардкодом.
- `background.js` пускает на скачивание только адреса с `*.twimg.com` (`isAllowedMediaUrl`) — защита от поддельных `postMessage` со страницы. Если X переедет на другой домен для медиа, скачивание отвалится с `url is not on twimg.com` при живых кнопках.
- `inject.js` внедряется немедленно, без ожидания `DOMContentLoaded`: иначе теряются первые ответы GraphQL и у постов первой отрисовки нет кнопок.
