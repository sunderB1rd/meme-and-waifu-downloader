# Waifu and Meme Downloader

Расширение для Firefox и Chrome. Добавляет кнопку скачивания к постам в X (Twitter) — видео, GIF (конвертируются в настоящий .gif), картинки — и к постам с картинками на Reddit.

Полная документация — в `README.md`, включая таблицу диагностики поломок и список уже наступленных граблей. Прочитай его перед серьёзными правками, особенно раздел «Когда сломается».

## Структура

Кроссбраузерность через общий код + два манифеста:
- `manifest.json` — Firefox (background как `scripts`)
- `manifest.chrome.json` — Chrome (background как `service_worker`, плюс permission `offscreen`)

Собирается через `node build.mjs` (запускать из корня репозитория) → `dist/firefox/` и `dist/chrome/`. Эти папки в git не попадают, генерируются заново по требованию. Версия — единый источник правды в `manifest.json`, скрипт сборки сам подтягивает её в chrome-манифест.

Исходники лежат в корне репозитория:
- `inject.js` — работает **внутри страницы твиттера** (не в мире расширения). Перехватывает `fetch`/`XMLHttpRequest`, вытаскивает ссылки на медиа из GraphQL-ответов. Самая хрупкая часть — X меняет структуру без предупреждения.
- `content.js` — изолированный мир расширения. Кнопки, DOM, имена файлов, санитизация путей, пайплайн конвертации GIF.
- `shared.js` — общие чистые функции: дефолты настроек, санитизация, имена файлов, сборка пути сохранения. Путь считается по виду медиа (`video`, `photo`, `redditVideo`, `redditImage`) — соответствие вида и ключей настроек задано списком `PATH_KINDS` явно, а не склейкой имени ключа: при склейке опечатка молча отправила бы файлы в корень загрузок. Там же список разрешённых для скачивания хостов и проверка адреса. Подключается перед `content.js` и перед `reddit.js`, в попапе и в фоновом скрипте; отдаётся как `globalThis.XVDShared`. Там же лежит иконка кнопки — одна на оба сайта. Обратно в `content.js`/`popup.js` эти функции дублировать нельзя: пока так и было, превью пути в попапе могло разойтись с тем, куда реально падает файл.
- `gif-encoder.js` — свой кодировщик GIF89a (median cut + LZW), без зависимостей. Подключается перед `content.js`, отдаётся как `globalThis.XVDGifEncoder`.
- `reddit.js` — content script только для reddit.com. Гифки и кадры галерей считаются картинками и складываются к ним; к видео относится только `post-type="video"`. На X гифка уходит в папку видео — там она и есть mp4, а здесь настоящий `.gif`, и расхождение это намеренное. Про X не знает ничего, общее у них — `shared.js` и `background.js`. Сеть не перехватывает: адреса одиночных картинок лежат в атрибутах `<shreddit-post>`, за галереей ходит в `<permalink>.json` и только по клику.
- `background.js` — единственное, что умеет качать. Подключает `shared.js` двумя разными способами: в Firefox его добавляет манифест (`background.scripts`), в Chrome фоновый скрипт это service worker, и там остаётся только `importScripts` — отсюда проверка `typeof importScripts` в первых строках файла. Создаёт blob URL (в Firefox сам, в Chrome через offscreen), ждёт завершения загрузки.
- `offscreen.html` / `offscreen.js` — только для Chrome, создаёт blob URL там, где в service worker это невозможно.
- `popup.html` / `popup.js` — настройки, тёмная тема, живое превью пути сохранения. Две вкладки, X и Reddit: у каждого сайта свои ключи в `storage.local`, общего между ними нет. Открытая вкладка хранится в `activeTab` — это состояние интерфейса, в `DEFAULT_SETTINGS` его нет намеренно, иначе content-скрипты таскали бы его вместе с настройками.

`build.mjs` кладёт `offscreen.*` в **обе** сборки — они в списке `SHARED`. В Firefox эти файлы просто лежат без дела, это не баг и «чинить» не нужно.

## Правила работы

- Комментарии в коде и README — на русском, интерфейс попапа — на английском. Не переводить одно в другое без явной просьбы.
- В попапе не использовать `<select>`: выпадающий список рисует система, и в тёмной теме он остаётся светлым — покрасить его нечем, пробовали. Выбор из нескольких вариантов делать сегментами на радиокнопках (`.segmented`). Там же не полагаться на `:has()`: он появился в Firefox только в 121-м, а `strict_min_version` у нас 115.
- Правишь попап — помни, что `check.mjs` сверяет id между `popup.js` и `popup.html`: опечатка в id иначе даёт пустое окно без единого сообщения об ошибке.
- После любой правки: `node check.mjs` — синтаксис, манифесты, совпадение версий, сборка и тесты одним прогоном. Он же пересобирает `dist/`, отдельный `node build.mjs` после него не нужен.
- Чистые функции покрыты тестами в `tests/` (встроенный `node:test`, без зависимостей). Правишь `shared.js` или `gif-encoder.js` — прогоняй тесты, они ловят ровно то, что в браузере проявляется молча.
- После правок — предложить, как переустановить расширение в браузере для проверки. Отдельно собирать не нужно: `check.mjs` уже пересобрал `dist/`.
- Версию в `manifest.json` поднимать при каждой пересборке, которая пойдёт на подпись (`web-ext sign` не принимает повторный номер).
- Тестирование — через `about:debugging` (Firefox) или `chrome://extensions` (Chrome) с распакованной папкой из `dist/`. После правок content script нужна полная перезагрузка вкладки твиттера, не только reload расширения.
- Не использовать сторонние npm-библиотеки без явного запроса — текущий подход: минимум зависимостей, весь код читаемый и правится вручную.
- Готовые архивы (.zip) в репозиторий не коммитить — это результат ручной упаковки для передачи файлов, гиту они не нужны.

## Не переименовывать

Префикс `xvd` — наследство от старого имени папки (`xvd-extension/`, исходники подняты в корень 14.08.2026). Имя устарело, но сами строки менять **нельзя**:

- **`"id": "xvd-extension@local.personal"`** в `manifest.json` → `browser_specific_settings.gecko`. Для Firefox id — это тождество расширения. Другой id = другое расширение: слетают настройки пользователя в `storage.local` и рвётся связь с уже подписанными на AMO сборками.
- **`source: "xvd-extension"`** в `postMessage` между `inject.js` и `content.js` — метка канала, по которой получатель отсеивает чужие сообщения со страницы. Значение произвольное, но должно совпадать на обеих сторонах; к имени папки отношения не имеет.
- **Префиксы `xvd-` в CSS-классах** (`xvd-photo-container` и прочие) и **ключи `dataset.xvd*`** (`xvdTweet`, `xvdKey`, `xvdBusy`). Живут одновременно в `content.js`, `reddit.js` и `style.css`, переименование требует синхронной правки всех трёх и ничего не даёт.

Если захочется навести красоту — это отдельная задача с полной переустановкой расширения и потерей настроек, а не попутный рефакторинг.

## Подпись и артефакты

- Последняя подписанная на AMO версия — **1.11.2**. В `manifest.json` сейчас 1.12.0, она ещё не подписана, так что этот номер можно расходовать. После подписи 1.12.0 поднимать снова: повторно номер не примут.
- Подписанные `.xpi`, архивы и `.amo-upload-uuid` хранятся **вне репозитория**, в `c:\Projects\meme-and-waifu-downloader-artifacts\`. В git им делать нечего, но и терять их не нужно: пересоздать `.xpi` для уже израсходованной версии невозможно.
- `web-ext sign` запускается из `dist/firefox/`, а не из корня: он пакует ту папку, из которой вызван, и из корня в сборку уехали бы README, `build.mjs` и сам `dist`.
- Ключи AMO лежат в `~/.web-ext-config.mjs` (домашняя папка, вне репозитория) — `web-ext` подхватывает их сам. **В командной строке ключи не передавать** и в репозиторий не класть ни под каким видом: `web-ext` читает ещё и `web-ext-config.mjs` из рабочей папки, но это репозиторий.

### Автообновления

`update_url` в `manifest.json` указывает на `updates.json` в корне репозитория, который отдаётся через `raw.githubusercontent.com`. Firefox читает `update_url` **из уже установленного расширения**, поэтому поле начинает работать только со следующей подписанной версии после его добавления — задним числом обновить тех, у кого стоит сборка без него, невозможно.

`updates.json` генерируется скриптом `release.mjs` из версии в манифесте, руками его не править. Ссылка в нём ведёт на ассет релиза с тегом `v<версия>` — **имена файлов при заливке на GitHub переименовывать нельзя**, иначе обновления отвалятся молча, без единого сообщения.

`updates.json` не входит в `SHARED` и в расширение не попадает: это метаданные для сервера, а не часть сборки.

### `release.mjs`

`node release.mjs` — пересборка плюс архивы в папку артефактов. `node release.mjs --sign` — то же плюс подпись, после которой `.xpi` кладётся туда же под внятным именем. Подпись отделена флагом намеренно: номер версии расходуется на AMO безвозвратно, обычный прогон должен быть безопасным.

Архивы собираются через **bsdtar** (`C:\Windows\System32\tar.exe`), и это не вкусовщина. `Compress-Archive` из Windows PowerShell 5.1 пишет пути с обратными слэшами вопреки спецификации ZIP: Windows такое читает, а macOS и Linux создают файлы с буквальным `\` в имени, и «загрузить распакованное» в Chrome ломается. Не возвращать `Compress-Archive`.

Имена файлов внутри архива перечисляются явно, а не через `.` — иначе каждая запись получает префикс `./`, а манифест должен лежать ровно в корне.

## Известные хрупкие места (см. README подробнее)

- Адреса картинок в ленте твиттера идут без расширения файла, из API — с ним. Сравнение через `baseMediaKey()`, режет и то и другое.
- React переписывает `className` контейнеров при перерисовке — класс `xvd-photo-container` восстанавливается на каждом проходе, в CSS есть запасной селектор. Контейнер он может и заменить целиком, переиспользовав сам `<img>`, поэтому пропуск картинки в `addPhotoButtons` проверяет не только `dataset.xvdKey`, но и наличие самой кнопки.
- DOM-узлы переиспользуются при скролле — кнопки помнят свою принадлежность через `dataset`, а не WeakSet.
- Размер и цвет иконки снимаются с соседней кнопки через `getComputedStyle`, не хардкодом: иконка 18.75px в ленте и 22.5px на странице поста, цвет зависит от темы. Размер кнопки — измерением соседа с запасным «иконка + 8px по краям»; множитель здесь не годится, отступ у круга постоянный. Цвет уходит в переменную `--xvd-icon-color`, иначе инлайновый `color` перебил бы hover и подсветку результата.
- `background.js` пускает на скачивание только адреса с хостов из `ALLOWED_MEDIA_HOSTS` (`twimg.com`, `redd.it`) — защита от поддельных сообщений со страницы. Список и проверка лежат в `shared.js` и покрыты тестами (`tests/allowlist.test.mjs`): ошибка здесь ничего не ломает внешне, расширение просто начинает качать то, что ему подсунули. Сверка идёт по точке перед доменом, а не по концу строки, иначе `evilredd.it` прошёл бы как свой. Если сайт переедет на другой домен для медиа, скачивание отвалится с `url host is not allowed` при живых кнопках. Список расширять поимённо, целыми доменами вроде `reddit.com` — нельзя.
- На реддите адрес картинки брать **только** из `content-href` у `<shreddit-post>`, а не из `<img src>`: у постов со спойлером в `src` лежит замыленное превью, и скачается мазня.
- Галерею реддита разбирать **только** через `<permalink>.json`: в DOM карусель ленивая (`fetch-ahead-count`), и в галерее на полтора десятка картинок в разметке будет несколько первых. Порядок брать из `gallery_data.items` — у ключей `media_metadata` он свой. И лезть строго в первый листинг ответа: во втором комментарии, у них бывает собственный `media_metadata` с гифками giphy.
- Карточка поста на реддите целиком накрыта ссылкой `<a slot="full-post-link">`, поэтому кнопке нужен `stopPropagation` и z-index выше 3 — иначе клик открывает пост.
- Панель действий поста (`<rpl-action-bar>`) живёт в **теневом дереве** `shreddit-post`, и `style.css` туда не достаёт. Кнопка в панели (у галереи «скачать всё», у остальных постов просто «скачать») поэтому вставляется в светлый DOM поста с атрибутом `slot`, а в панель попадает через слот — так она остаётся в дереве документа и стили на неё действуют. Имя слота не угадывается: `placeInActionBar` перебирает список и проверяет `assignedSlot`. Если ни один не подошёл, кнопка садится вторым кружком поверх картинки.
- **В слот `share-button` садиться нельзя.** У слота бывает запасное содержимое, и оно показывается ровно до тех пор, пока в слот ничего не назначено. Мы туда сели — и у постов с нашей кнопкой пропала родная кнопка «поделиться». По той же причине запрещены `mod-content-actions` и `promote-post-button`: там инструменты модератора. Брать можно только пустые слоты или уже чем-то занятые — сейчас это `repost-button` (встаём следом за выпадашкой репоста) и `action-row-whitespace`.
- Вид кнопки в панели реддита снимается с соседней родной через `getComputedStyle` (фон, высота, радиус, отступы, шрифт) и уходит в CSS-переменные `--xvd-*`. Числами задавать нельзя: фон у родных кнопок полупрозрачный и рассчитан на любой фон под ним. Наведение и нажатие тоже сняты оттуда: `getComputedStyle` отдаёт и пользовательские свойства, поэтому цвета состояний забираются из переменных самого реддита (`--button-color-background-hover`, `--button-color-background-active`, `--color-interactive-pressed`). Конструкция нажатия повторена как у них — сплошная заливка `linear-gradient` поверх фона активного состояния, то есть подмешивание, а не замена.
- Панель гидратируется позже карточки, поэтому у размещения есть ограниченный повтор (`PLACEMENT_RETRIES`). Без предела он пересоздавал бы кнопку каждый кадр на прокрутке.
- У поста `post-type="gif"` в `content-href` лежит настоящий `.gif` на i.redd.it, поэтому он идёт тем же путём, что и картинка. Через `collectVideo` его пускать нельзя: у плеера гифки нет `packaged-media-json`, а в API нет `reddit_video`, и скачивать оказалось бы нечего.
- В галерее анимированные кадры (`e: "AnimatedImage"`) идут вперемешку с обычными. Запасной адрес у них в `s.gif`, а не в `s.u` — у анимированных такого поля просто нет.
- Ссылки на видео со звуком живут **только в разметке**: атрибут `packaged-media-json` у `<shreddit-player>`, в ответе `.json` их нет. Плеер ищется по `post-id`, а не по сохранённой ссылке на узел, — карточки переиспользуются при скролле. Ссылки подписаны и протухают (параметры `e` и `s`), поэтому читать их надо в момент скачивания, а не запасать впрок.
- Из готовых mp4 берётся максимальное разрешение, при равном — H264, а не VP9: в mp4 его понимают все, включая проводник и видеоредакторы. Если готового набора нет, остаётся `reddit_video.fallback_url` — это дорожка **без звука**, и для роликов со звуком нужен мультиплексор, которого пока нет.
- Номер кадра карусели берётся из `slot="page-N"` у элемента с `visibility: visible` — он совпадает с порядком в `gallery_data.items`. Индекс спрашивается в момент клика: между появлением кнопки и нажатием галерею могли пролистать.
- `inject.js` внедряется немедленно, без ожидания `DOMContentLoaded`: иначе теряются первые ответы GraphQL и у постов первой отрисовки нет кнопок.
- `API_PATTERN` в `inject.js` ловит **все** запросы к `/graphql/`, а не список имён операций. Список приходилось дополнять после каждого переименования у X, и на странице пользователя кнопки из-за этого пропадали. Не возвращать фильтр по именам: отбор делает `processTweetNode`, который пропускает узлы без медиа.
