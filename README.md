# Waifu and Meme Downloader

Расширение для Firefox и Chrome. Добавляет кнопку скачивания к постам в X (Twitter): видео, GIF и картинки, в оригинальном качестве, с осмысленными именами файлов.

---

## Что оно умеет

- Кнопка в панели действий поста скачивает **всё медиа сразу**. Если файлов больше одного, на кнопке появляется бейдж с их количеством.
- Кнопка поверх каждой картинки (по наведению) скачивает **только её**. Работает и в ленте, и в полноэкранном просмотрщике.
- Картинки сохраняются в родном формате — PNG остаётся PNG, а не пережимается в JPEG.
- Имя файла: `автор_ГГГГ-ММ-ДД_idПоста.расширение`. У GIF добавляется `_gif`, у нескольких файлов из одного поста — `_1`, `_2` и так далее.
- В настройках: отдельные подпапки для видео и картинок, раскладка картинок по авторам, «спрашивать каждый раз».

## Установка

### Firefox — временно (для разработки)

1. `about:debugging#/runtime/this-firefox`
2. **Load Temporary Add-on** → выбрать `dist/firefox/manifest.json`
3. Слетает при перезапуске браузера. Для постоянной установки — см. «Подпись» ниже.

### Firefox — постоянно (подписанный `.xpi`)

Firefox не ставит неподписанные расширения насовсем, даже свои. Подпись бесплатная, публикация в каталоге при этом не нужна.

1. Завести аккаунт на `addons.mozilla.org`, получить ключи на странице `.../developers/addon/api/key/` — понадобятся **JWT issuer** и **JWT secret**.
2. Установить утилиту: `npm install --global web-ext` (нужен Node.js).
3. Из папки `dist/firefox`:

   ```
   web-ext sign --api-key="ключ" --api-secret="секрет" --channel=unlisted
   ```

   `unlisted` = подпись лично для себя, без публикации и без ревью человеком.
4. Готовый `.xpi` появится в `web-ext-artifacts`. Перетащить его в окно Firefox или поставить через `about:addons` → шестерёнка → «Установить дополнение из файла».

**Важно:** перед каждой новой подписью поднимать `version` в `manifest.json`. AMO не примет повторно тот же номер, даже если предыдущий файл удалён.

### Chrome

Подпись не нужна, но и постоянной установки без магазина не бывает — расширение живёт как распакованное.

1. `chrome://extensions`
2. Включить **Режим разработчика**
3. **Загрузить распакованное** → указать папку `dist/chrome`

Chrome при каждом запуске будет показывать плашку про расширения в режиме разработчика — это нормально, её нужно просто закрывать.

## Разработка

```
node build.mjs
```

Собирает `dist/firefox/` и `dist/chrome/` из общих исходников. Отличаются только манифесты, весь код общий.

**Цикл работы:** правишь исходники → `node build.mjs` → в `about:debugging` жмёшь Reload у расширения → **обязательно перезагружаешь вкладку с твиттером** (Ctrl+Shift+R).

Про перезагрузку вкладки легко забыть, и тогда кажется, что правки не применились: content script внедряется в страницу один раз при загрузке, кнопка Reload его в открытых вкладках не обновляет.

**Если подписанная версия уже стоит в браузере**, временную поверх неё загрузить не выйдет — у них одинаковый ID. Отключи подписанную в `about:addons` на время работы (настройки при этом сохранятся), либо заведи отдельный профиль Firefox через `about:profiles`.

**Версия** задаётся в `manifest.json`. `build.mjs` сам подтянет её в chrome-манифест, руками синхронизировать не нужно.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `gif-encoder.js` | Свой кодировщик GIF89a: median cut для палитры + LZW. Подключается перед `content.js` и отдаётся через `globalThis.XVDGifEncoder`. |
| `inject.js` | Работает **внутри страницы**. Перехватывает `fetch` и `XMLHttpRequest`, которыми X подгружает посты, и вытаскивает из ответов ссылки на медиа. Самая хрупкая часть. |
| `content.js` | Работает в изолированном мире расширения. Принимает данные от `inject.js`, расставляет кнопки, следит за DOM, собирает имена файлов и пути. |
| `background.js` | Единственное, что умеет качать: `downloads.download`. Ждёт завершения и возвращает статус, чтобы кнопка мигнула зелёным или красным. |
| `popup.html` / `popup.js` | Настройки. |
| `style.css` | Стили кнопок, которые вставляются в страницу твиттера. |
| `manifest.json` | Firefox. Фоновый скрипт как `scripts`. |
| `offscreen.html` / `offscreen.js` | Только для Chrome. Создаёт blob URL для готового GIF — в service worker это невозможно. В Firefox файлы лежат без дела. |
| `manifest.chrome.json` | Chrome. Фоновый скрипт как `service_worker`, разрешение `offscreen`, без gecko-полей. |

Настройки лежат в `storage.local` под ключами `videoSubfolder`, `videoAlwaysAsk`, `photoSubfolder`, `photoAlwaysAsk`, `photoByAuthor`, `gifConvert`. Они переживают обновление и переустановку расширения — если что-то ведёт себя странно, стоит заглянуть туда первым делом.

## Когда сломается

Сломается почти наверняка: расширение опирается на внутреннюю структуру ответов X, а её меняют без предупреждения. Симптом всегда один — **кнопки просто перестают появляться**.

### Порядок диагностики

**Шаг 0. Проверить разрешения.** `about:addons` → расширение → «Разрешения» → доступ к данным для сайтов. Firefox иногда сбрасывает их при обновлении, и тогда скрипт просто не запускается. Выглядит как поломка кода, но чинится одним переключателем.

**Шаг 1. Открыть консоль на вкладке твиттера** — F12 прямо на странице x.com. Не в окне отладки расширения: это разные консоли, и логи из `content.js` идут именно в консоль страницы.

**Шаг 2. Понять, докуда доходит.** Временно вернуть отладочные логи (они убраны из релиза):

- в начало `content.js`: `console.log("[XVD] content.js загружен");`
- в начало `inject.js`: `console.log("[XVD] inject.js загружен и активен");`
- в обработчик сообщений в `content.js`: `console.log("[XVD] пришло медиа", tweetId, JSON.stringify(info));`

Дальше по тому, что видно:

| Что в консоли | Где искать причину |
|---|---|
| Ничего вообще | Скрипт не запустился. Разрешения, домен в `content_scripts.matches`, вкладка не перезагружена. |
| `content.js` есть, `inject.js` нет | Не проходит внедрение. Смотреть `web_accessible_resources` и ошибки CSP. |
| Оба есть, но «пришло медиа» не появляется | **Самый вероятный случай.** X переименовал операции GraphQL — чинить `API_PATTERN` в `inject.js`. |
| Медиа приходит, кнопок нет | Изменилась вёрстка. Чинить селекторы в `content.js`. |
| Кнопки есть, в консоли `url is not on twimg.com` | X отдаёт медиа с нового домена. Фоновый скрипт пускает на скачивание только `*.twimg.com` — править `isAllowedMediaUrl` в `background.js`. |

### Что именно править

**`API_PATTERN` в `inject.js`** — список имён операций (`TweetDetail`, `HomeTimeline` и прочие). Открыть вкладку Network, отфильтровать по `graphql`, посмотреть, как теперь называются запросы, которые возвращают ленту, и добавить новые имена в регулярку.

**Разбор ответа** — функция `processTweetNode`. Она ждёт узлы с полем `legacy`, а внутри `extended_entities.media`. Если структура изменилась, проще всего скопировать сырой ответ из Network в редактор и посмотреть, где теперь лежат `video_info.variants` и `media_url_https`.

**Селекторы вёрстки в `content.js`:**

- `article[data-testid="tweet"]` — карточка поста
- `div[role="group"]` (берётся последняя) — панель с кнопками ответа, репоста, лайка
- `img[src*="pbs.twimg.com/media/"]` — картинки
- `div[data-testid="tweetPhoto"]` — контейнер картинки

### Уже наступленные грабли

Это то, что чинилось по ходу дела — если поведение вернётся, причина известна.

**Адреса картинок в ленте идут без расширения файла, а из API — с ним:** `/media/ABC` против `/media/ABC.jpg`. Поэтому сравнение идёт по функции `baseMediaKey`, которая отрезает и query, и расширение. Если сопоставление вдруг перестанет работать — смотреть сюда.

**React стирает наши классы.** При перерисовке твиттер переписывает `className` контейнера своим значением, и класс `xvd-photo-container` пропадает — кнопка остаётся в DOM, но перестаёт показываться по наведению. Поэтому класс проставляется заново на каждом проходе, а в CSS есть запасной селектор через `div[data-testid="tweetPhoto"]`.

**Узлы переиспользуются при скролле.** Кнопка помнит свой пост в `dataset.xvdTweet`, картинка — свой файл в `dataset.xvdKey`. Без этого кнопка на переиспользованном узле качала бы медиа от предыдущего поста.

**Размер иконки различается:** 18.75px в ленте и 22.5px на странице открытого поста. Меряется через `getComputedStyle` соседней иконки, размер кнопки выводится как иконка × 1.8.

## Ограничения

- **Сохранять можно только внутрь папки загрузок.** Ограничение API браузера: абсолютные пути и `..` отклоняются. Обход — junction на нужную папку:
  `mklink /J "%USERPROFILE%\Downloads\TwitterImages" "D:\Art\Twitter"`
  (папки с таким именем в загрузках до этого быть не должно).
- **Качество видео** всегда максимальное из доступных, выбора нет.
- **GIF конвертируются по-настоящему.** В X настоящих gif нет — то, что помечено значком GIF, это зацикленный mp4 без звука. Расширение вытаскивает кадры через `<video>` + canvas и собирает `.gif` своим кодировщиком (`gif-encoder.js`, без сторонних библиотек). Отключается тумблером «Convert GIFs to real .gif», тогда сохраняется исходный mp4.

  Что об этом стоит знать:
  - Палитра GIF — 256 цветов, поэтому плавные градиенты станут грубее оригинала.
  - Файл обычно тяжелее исходного mp4, иногда заметно.
  - Конвертация занимает несколько секунд, кнопка всё это время в состоянии загрузки.
  - Параметры зашиты константами в начале `content.js`: `GIF_FPS` (12.5), `GIF_MAX_WIDTH` (480), `GIF_MAX_FRAMES` (150), `GIF_MAX_SOURCE_BYTES` (15 МБ). Если гифки выходят слишком тяжёлыми — уменьшать ширину и частоту кадров.
  - Готовый файл уходит в загрузки как blob URL. В Firefox его создаёт фоновый скрипт, в Chrome — offscreen-документ (`offscreen.html` / `offscreen.js`), потому что в service worker нет `URL.createObjectURL`, а `data:` URL браузеры в загрузках не принимают. Если и это не сработает, останется запасной путь через ссылку — тогда **подпапка из настроек не учитывается**.
- **Индикатор может соврать.** Фоновый скрипт в MV3 браузер вправе выгрузить при простое. Если это совпадёт с ожиданием завершения загрузки, кнопка мигнёт красным, хотя файл скачается нормально.
- Скачивание больших видео дольше 20 секунд считается успешным по таймауту — дальше статус виден в обычном менеджере загрузок.
